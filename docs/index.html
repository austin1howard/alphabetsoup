Design

One session. Shared opinions.

Current models handle a whole task in one context. Splitting work across agents adds hand-offs and re-explained context, and costs more tokens than it saves. What's still worth packaging is the opinion, so the code looks familiar when you review it.

// conventions

Loaded when the language is

Each language plugin carries its library picks, patterns, anti-patterns, layout, and testing setup. Claude loads them before it writes that language, so only the stacks a repo actually uses cost context.

// structure

Every repo has the same shape

One layout, one project-guide format (summary, golden rules, layout, commands), and the same make targets everywhere. Claude runs make, never the raw tool, so the commands CI runs match the ones you run.

// throughline

Specs carry intent over time

Product, architecture, domain, features, decisions. Each spec says what the system does and why, and is updated in the same change as the code, so the code is always reviewed against the current spec.

// review

Paired, then independent

Walk a diff stop by stop, tour an unfamiliar codebase, or trace an error back to its cause, together. When a second opinion matters, a reviewer and a security reviewer each check the change in a fresh context.

Plugins

A core plugin, plus one per language.

Each language plugin ships its conventions and a scaffold (init, Makefile, Dockerfile, CI recipe). Enable only the ones your stack uses.

Install

Register the marketplace, then bootstrap.

1
Register the marketplace in your project's .claude/settings.json. 
{
  "extraKnownMarketplaces": {
    "alphabetsoup": { "source": { "source": "github", "repo": "austin1howard/alphabetsoup" } }
  }
}
2
Install the core plugin and bootstrap. 
/plugin install alphabetsoup@alphabetsoup
/alphabetsoup:bootstrap

Bootstrap detects or asks for your stack, enables the language plugins, and scaffolds the repo. On an existing repo it lists the gaps and changes only what you approve.

Skills

Four commands. The rest loads on its own.

Standards, the testing bar, specs, and each language's conventions load automatically when the work calls for them.

/alphabetsoup:bootstrap

Bootstrap

Scaffold a new repo or adopt an existing one: layout, project guide, make targets, specs, Docker, compose, CI.

/alphabetsoup:ci [github|gitlab]

CI

Lint, typecheck, test, build, and release, each its own job per domain. Every job runs one make target, so switching providers just regenerates one thin file.

/alphabetsoup:walkthrough

Walkthrough

A diff, a codebase tour, or "how does X work / why this error". One stop at a time with line references; it waits for you, and records the changes you ask for.

/alphabetsoup:review

Review

Independent fresh-context review: correctness and conventions, security, or both. Findings come back ranked with fixes.
